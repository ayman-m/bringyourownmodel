01 What Guardian Is & The Agent Loop

Guardian runs on an incident. The pack ships one incident type — Guardian Agent Run — wired to the GuardianAgentLoop playbook and the GuardianAgentRunLayout layout.

The playbook fires the automation GuardianReasoningTick exactly once; from there the script owns all re-entry. GuardianReasoningTick has polling:true and self-reschedules via a ScheduledCommand with its own bare name — each re-invocation is one model turn plus its tool calls. All evolving state (transcript, tick counter, cost) round-trips through the incident's Guardian.Loop.* Context, never through args.

Per-tick sequenceStops the loop when…
1 · kill-switch check → 2 · (tick 0) build prompt + tool catalogue → 3 · one guardian-llm-chat turn → 4 · charge cost → 5 · dispatch new tool calls through the bridge → 6 · persist Guardian.Loop & reschedule kill switch on · model concludes (no tool calls) · MAX_TICKS 25 ceiling · a loop-defense guard trips
  • Autonomously: the GuardianIntakeSweep job opens a Guardian Agent Run incident every 6h and runs a read-only triage sweep — the autonomy heartbeat.
  • Manually: create a Guardian Agent Run incident and move it to investigating; GuardianAgentLoop attaches and runs. Live proof: incident #29605 ran 3 ticks → completed, cost $0.008491.

02 The Security Model — Default-Deny Chokepoint

The single most important fact: the tool list shown to the model is not a security boundary. The model can emit tool_calls for commands it was never offered. The real boundary is one automation — GuardianToolBridge — the only place a model-proposed command reaches executeCommand.

GATE 1
Kill switch
guardian_kill_switch — halts all dispatch.
GATE 2
Denylist
generic REST verbs + destructive commands, fail-closed.
GATE 3
Default-deny
on the 33-cmd allowlist or classified in policy — else denied + audited.
GATE 4
Policy tier
allow / require_approval / deny.

03 Operating — Jobs, Model, Budgets, Modes

Once installed, Guardian runs itself. Three Time-Triggered jobs — all Enabled / Running (0 error, 0 disabled) — drive autonomy and upkeep; each sets closePrevRun:true so runs never pile up.

JobCadenceWhat it does
GuardianIntakeSweep6hAutonomy heartbeat — opens a Guardian Agent Run incident & runs a read-only triage sweep (recommend-only).
GuardianHousekeeping1hConsolidates/shards audit, reaps stale approvals + expired memory, watchdogs stalled loops.
GuardianEvalScore1hScores newly-concluded eval incidents into guardian_eval_results.
