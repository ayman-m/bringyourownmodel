
#### Guardian for the Cortex platform 1.0.0

First release of the Cortex platform edition of Guardian. It carries everything in the XSOAR 6 pack at 1.0.1 (the re-entrant reasoning loop,
the tool bridge, the model-profile adaptation Job, the SPL write hold) plus the Cortex platform adaptations listed in `DIVERGENCE.md`:

- Targets `marketplacev2`; playbooks carry `adopted: true` and must be adopted after install (see the runbook).
- Model and compaction calls send their JSON arguments base64-encoded; the integrations and GuardianCompact accept both forms.
- The tool risk tier, policy list and allowlist know Cortex platform's native `core-*` / `xdr-*` commands: every write is held for
  approval, and read tools (`core-get-issues`, `core-get-cases`, `core-get-endpoints`, XQL) are offered to the agent.
- Jobs are `##default##` jobs; a Job run has no issue attached.
- The pre-process rule is not shipped (it never fires on Cortex platform).
- Adds the Guardian Foundry model-plane integration (Microsoft Foundry / Azure AI Foundry); see the XSOAR 1.0.1 notes. This copy also accepts base64-encoded JSON arguments.

- **Issue creation.** Cortex platform has no create-issue command, so `GuardianSimulateIncidents` and `GuardianSocAgentCreateInvestigation` insert an alert through the Core REST API (`core-api-post` to `/public_api/v1/alerts/insert_parsed_alerts`) with the tenant's own identity, find the new issue by name and tag it. No API key is stored.
- **Playbook `GuardianInvestigateIssue`.** Investigates the issue it is attached to: `!setPlaybook name=GuardianInvestigateIssue` in the issue's War Room.
- **Guardian Foundry** and the **content-filter retry** are included, as in the XSOAR 6 pack 1.0.1.
- Install from the pack zip, then create the Jobs and adopt the playbooks with the install tools (`docs/INSTALL.md`).
