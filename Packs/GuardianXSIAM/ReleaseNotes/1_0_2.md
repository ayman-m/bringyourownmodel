#### Scripts

##### GuardianReasoningTick

- A run now clears the verdict fields left on the incident by an earlier run when it starts. Before, the old verdict came back in the model's own `getIncidents` result and could be copied into the new verdict, and a run that ended without a verdict left the old one in place.
- A failed verdict write is now audited as an error (it was recorded as ok while the summary fields stayed empty), and the per-tool call counts of an earlier run are forgotten when the same incident is investigated again.
- New argument `scope_to_incident`. When true, `getIncidents` and `getEntries` may only read the run's own incident; a call for another incident, or for none, is refused with an explanation and the model is pointed to `SearchIncidentsV2`. A four-alert test showed a model listing the open queue and writing up the first incident it found.
- The incident-scope message no longer forbids the narrow `SearchIncidentsV2` for similar earlier incidents that the investigation prompt asks for.
- A model with no row in `guardian_pricing` is now named once per run in the loop output instead of silently costing USD 0.
- The run now records what it did on the incident, every tick, next to the cost: `guardianmodel`, `guardiantoolcalls`, `guardiantoolfailures` (errors, denials, blocks), `guardianapprovalsrequested` and `guardiantoolsused` (the tool names in call order), plus `guardiangateaction` (`nudged` or `downgraded` when the conclusion check acted). These feed the Guardian Performance dashboard.
- A final answer is now checked before the verdict is recorded. A Benign or Malicious verdict above confidence 70 needs corroboration from a tool result in the run (an enrichment or lookup); the alert itself, a similar earlier incident and a knowledge-base search do not count. The model gets one corrective turn to gather evidence or lower the verdict; if it is still unsupported the verdict is recorded as Suspicious at confidence 65 or lower, with a note. In a run scoped to one incident (`scope_to_incident`), the model also gets that one turn when it skipped the case note or the memory store. A ten-alert test had a Benign 90 "validated as authorized" with nothing checked, a Malicious 85 on a public-bucket alert (and later a Malicious 95 that cited a similar incident and an ATT&CK mapping), and four runs with no memory entry.
- If the corrective turn produces no verdict (for example a malformed tool call or an empty turn), the verdict the gate held back is now recorded under the same rule, instead of the run ending with no verdict.
- A tenant that cannot store custom issue fields (for example Cortex Cloud) no longer gets a false "no verdict" for a run that reached one. A verdict that is valid but could not be saved to the issue fields now counts as produced: the run no longer takes a corrective retry or an extra extraction call, and the loop output says once that the verdict is in the conclusion and `guardian_audit` but not in the issue fields. The `verdict_write` audit row (status `ok`, `error` or `skipped`, the new `skipped` meaning issue-field writes are off) keeps the verdict, confidence and techniques. The first failed issue-field write in a run now switches the run's field writes off, with one warning instead of one on every turn (cost stays in `guardian_cost_ledger`). New setting `incident_fields_enabled` in `guardian_settings` (default `true`): set it to `false` to skip every issue-field write from the start, with no warning. The reasoning trace shows the verdict recorded in the run when the `guardianverdict` field is empty, instead of "pending".
- The model's size now follows the model. A model that is in `guardian_model_catalog` gets the size class the catalogue gives it (small under 13B total parameters, medium 13B to 40B, large over 40B; a closed hosted model of unpublished size counts as large), looked up on every run; nothing is stored in the profile records, so a profile written earlier gets its size with no rewrite. The order is the operator's pin (`overrides.model_tier`), then the catalogue, then an explicit `guardian_settings.model_tier`, then small. The model profile line of each run shows the size with its source.
- The limits that depend on the model now scale with its input budget (in Guardian's token estimate, 4 characters per token): one tool result may take 20% of the budget (never less than 16384 bytes), the incident details pinned into the prompt 5% (never less than 2000 characters), and the history is compacted by tokens against the budget instead of by a 25-message count. A tool result is cut to head and tail at that ceiling (head, marker and tail together come to the ceiling), and when one turn asks for several tools they share 30% of the budget. For example, with gpt-5-mini (budget 173,400) a 69 KB result previously reached the model as about 9 KB and a 41 KB skill as about 8 KB.
- Every request is held to the input budget. The compaction that saves the transcript, the pre-flight before a model turn and the forced summary turn that follows a stop all drop the oldest turns by tokens, with the tool list counted in; the forced summary turn had no pre-flight of its own before.
- The repeated-call record keeps at most 32,768 characters of each large result, so the saved loop state does not grow by a full result per tick.
- After the conclusion-quality gate sends a conclusion back for another turn, the posted conclusion is now the analysis from the held reply (without its verdict block), a blank line, and the final reply, so the War Room keeps the evidence and the rationale. It is not repeated when the final reply already contains it, and the verdict is still taken from the final reply alone.
- The model-size dropdown check compares the size the run uses, not the raw `guardian_settings` value. An instance dropdown of `auto` is no declaration, and a stale value on a model whose size comes from the catalogue gives one short note instead of a warning.
- The system prompt, the incident pin and the task are never dropped or summarized: token compaction and the summarizing path both keep them verbatim, and the newest turn's tool results are cut (head and tail) to fit rather than dropped. Each turn's per-result limit is also clamped to the room the request has left after those and the tool list, and the tool bridge is handed the same number. If the prompt, the pin and one full result cannot fit, the lowest-priority tools are left out of the turn first.
- The dropped-transcript archive is bounded by size (2 MB by default, `guardian_settings.dropped_transcript_max_bytes` to change it; the oldest rows go first) and each archived message is cut to the per-result limit.
- The held analysis is cut at the verdict block exactly where the verdict parser finds it, including a verdict object in the middle of the reply.
- The turn limit per run now follows the model's size: 25 turns for a small model (as before), 40 for a medium one and 60 for a large one. It resolves like the other model numbers: `overrides.max_ticks` in `guardian_model_profile`, then an explicit `MAX_TICKS` in `guardian_settings`, then the size's value. The forced summary, the narration and the model profile line use the resolved limit. The polling window of the self-rescheduling loop is now sized from the limit (turn limit x (cadence + 120 s), never under 1200 s), so a 60-turn run is not cut off by the platform's polling timeout.

##### GuardianCommon (embedded in every script)

- Small and medium model sizes now run one tool call per turn by default (`max_tool_calls_per_turn`; large keeps no limit, and an operator override still wins). Models that batch calls skip steps and write notes before they have the results.
- `guardian_resolve_model_params` takes the model's catalogue size as an optional third argument and returns `tier_source`, `tier_note`, `catalog_model` and a `limits` block (the per-result limit, head and tail, incident details, history rule, subagent and compaction caps), each with its source. `guardian_derive_limits` is the one place the budget-scaled numbers are worked out. The catalogue lookup (`guardian_catalog_lookup`, `guardian_catalog_load`) moved into this shared block. A large model's tool-list budget is 25% of the input budget (at least 24000, never over 60%). Its tool descriptions are cut at 1024 characters, a provider-safety limit (OpenAI-family function descriptions may be limited to that), which no allowlisted command exceeds.
- A model-profile snapshot or saved loop state written before this release has no `limits` and is resolved again.
- `GUARDIAN_TIER_PROFILES` has `max_ticks` (25 / 40 / 60) and `guardian_resolve_model_params` returns `max_ticks` with its source; a model-profile snapshot or saved loop state written before this release has no turn limit and is resolved again.

##### GuardianToolCatalogBuilder

- Four built-in commands (`getIncidents`, `getEntries`, `findIndicators`, `getList`) that the server describes with a localisation key (for example `commands.local.cmd.get.incs`) now carry a plain sentence, including the argument to use. A model had called `getIncidents` with a search query.
- New argument `model_params`: the agent loop passes the numbers it resolved, so the tool list and the loop use the same size and budget. The report line shows the size with its source and the derived limits. A tool description cap of 0 means no shortening (a large model).

##### GuardianModelProfileUpdate

- A probe that recommends an input budget below 20,000 tokens is no longer saved unless `force=true`. Guardian's own fixed prompt is about 17,000 tokens, so a smaller budget made the loop drop the task itself while compacting.
- The saved record now says where its figure comes from (`source`): `documented` (a probe that ran no window search, because the model's limits are in `guardian_model_catalog`), `confirmed` (the measured window is at least 80% of the documented limit, so the documented limit is used), `measured` (more than 20% below it, so the measured figure is used, with the evidence stated) or `quota` (the probe stopped on a tokens-per-minute error, so the documented limit is kept). A model that is not in the catalogue is saved as `measured`, as before. The existing checks (minimum usable budget, truncated result, `force`) still apply.
- New optional setting `max_input_tokens_cap` in `guardian_settings` (unset by default): no saved input budget is larger than it.

##### GuardianModelCommand

- `!guardian-model` now shows the model chosen in the Guardian Foundry **Model** dropdown. It resolved only the Deployment name, so an instance set from the dropdown with an empty Deployment name showed "(not set)". It now uses the dropdown choice, or the Deployment name for Custom and for instances saved before the dropdown existed (the same rule the integration uses).
- `!guardian-model` shows where each figure comes from: documented (with the catalogue date), confirmed, measured, quota or override. For a measured figure it shows the gap from the documented limit and the evidence; an older record without that comparison gets it from the catalogue.
- Before a profile is saved, `!guardian-model` now shows what the next investigation will use: for a model in `guardian_model_catalog` that needs no probe (or has a cloud provider cap) it shows the documented budget the "Resolve model profile" task will save, and says `!GuardianModelProfileCheck` saves it now. For a self-hosted open-weight model it keeps the settings budget and says a probe is needed. The "no profile yet" advice no longer depends on the GuardianModelAdaptation Job, so it also fits tenants without Jobs.
- `!guardian-model` shows the size with its source, the derived limits and the one-line note when `guardian_settings.model_tier` is not used; the preview for a model with no saved profile names its catalogue size.
- The instance table says the Model size dropdown is display-only and that the size comes from the model catalogue (it used to say a blank value fails safe to small).
- `!guardian-model` shows the turn limit and its source.

##### GuardianProbeModel

- `!guardian-probe-model` now looks the model up in the new `guardian_model_catalog` list after its warm-up call (by the configured model, then by the model the provider reports, so a custom deployment name still matches). A documented closed frontier model gets no window search (only the characters per token and the capability checks are measured); pass `force=true` to search it anyway. Any other known model is searched up to its documented usable input limit (the default `max_probe_tokens` is no longer a fixed 131072 for it; an unlisted model keeps 131072, and the report says how to raise it) and the result is compared with the documented limit.
- Probe calls ask for a one-word answer at `reasoning_effort` low, so a reasoning loop does not distort the timing; if a provider rejects the parameter the call is retried once without it and the parameter is dropped for the rest of the run.
- A size now counts as too slow only when its first response takes longer than the model's own small-prompt time plus the latency budget, so a reasoning model's fixed thinking delay is not counted as slowness. The per-call time limits and the 240 s run limit still apply.
- A quota error (HTTP 429, "rate limit", "quota", "tokens per minute") now stops the search and is reported as "quota reached at N tokens (tokens-per-minute limit), not a context limit; the window was not reached". The largest size that answered is used.
- The report shows the documented figure next to the measured one, with the verdict of the 20% rule. The Foundry **Model** dropdown is now read as the configured model.

##### GuardianModelProfileCheck

- The "Resolve model profile" task now saves a `documented` profile for a model in `guardian_model_catalog` when nothing better is on file, so a known model gets its documented limits without any command or Job. It does this only for a model that needs no probe or that has a cloud provider cap, only when there is no record for the instance or the record is for another model, never replaces a confirmed or measured record for the same model, never touches `overrides`, and writes nothing when nothing would change. A self-hosted open-weight model is never written automatically: the report gives its documented figure and says a probe is needed to confirm the served window.
- The report words each figure by its source (documented, confirmed, measured, override). A documented figure is never called measured or probed, and a documented profile does not trigger the stale-profile warning.
- The model's size is taken from the model catalogue on every run (found by the active record's catalogue id, else the configured model), and the report says so. When an explicit `guardian_settings.model_tier` is not used because the catalogue knows the model, one line says so and how to force a size. The report and the snapshot carry the derived limits.
- The report and the snapshot show the turn limit and where it came from.

##### GuardianSimulateIncidents

- Fixed `Unsupported Command : GuardianSimulateAlerts` when the script was uploaded as a single item. The platform build splits a script with "incident" in its name into the real code and a wrapper; the script now keeps one script under its own name (`skipprepare`).

##### GuardianCostLedger

##### GuardianToolBridge

- The operator-only set now includes the new button automations, so the model can never call them.
- New optional arguments `evidence_truncate_bytes` and `evidence_head_tail_bytes`: the size a tool result is cut to is now the per-result limit the agent loop derived for the model (a share of its input budget), clamped to 2048 - 8388608 bytes. Without them the bridge reads the run's own numbers, then resolves them. Only result shaping changed; no gate did.

##### GuardianCompact

- The incident pin and the task are never sent to the summarizer; they come back unchanged among the kept messages. `!guardian-compact` keeps them too.

##### GuardianSubagentDispatch

#### Lists

##### guardian_model_catalog

- New. The documented context limits (context window, maximum input and output, tool and structured-output support) of 146 commonly used models, checked 2026-10-09, with the cloud provider's own cap where it differs from the vendor's (for example gpt-4.1 on Azure). It is pack data like `guardian_pricing`: read-only at run time, rebuilt with `scripts/build_model_catalog.py`. Import it before running the new version.
- Every model now has `params_b` (total parameters in billions, from the model id or its card, else null) and `size_class` (small, medium, large, or null where the size is not stated). The size follows `params_b` whenever it is known (a closed 3B model is small); a closed hosted model of unpublished size is large; `ollama:command-r:35b` was added as an alias of Command R 08-2024.

##### guardian_settings

- Documented the optional `max_input_tokens_cap` setting (unset by default).
- `model_tier` now ships as `auto`: the model's size comes from the model catalogue. Set `small`, `medium` or `large` only for a model that is not in the catalogue; to force a size for a catalogued model use `overrides.model_tier` in `guardian_model_profile`. `evidence_truncate_bytes`, `evidence_head_tail_bytes` and `batch_cap` are no longer shipped: the limits they set are derived from the input budget (they remain valid optional overrides). The comment on `max_input_tokens` (28258) now says it is only the budget used until the model's window is known (from the catalogue for hosted models, from a probe for self-hosted ones). The thresholds in the comments are now one rule: under 13B small, 13B to 40B medium, over 40B large.
- `MAX_TICKS` is no longer shipped (it was 25 for every model): the turn limit follows the model's size and is documented as an optional override in `_comment_MAX_TICKS`.

##### guardian_pricing

- Added rows for `gpt-5-mini`, `gpt-oss-120b` (Azure Global Standard list price) and `cohere-command-a` (list prices) and an estimate for a self-hosted `command-r:35b`. The estimate is not a vendor price: replace it with your own rate.

##### Prompt tail (`guardian_prompt_tail`)

- New "Verdict calibration" section: the alert is the claim being checked, not evidence; Benign or Malicious above 70 needs a tool result that corroborates it; never write "validated" or "confirmed" without one; write the case note and store a memory entry before the verdict.

#### Integrations

##### Guardian Cohere

- The **Model size** dropdown has a new option **auto**, which is now the default. "auto" declares nothing: the size a run uses comes from the model catalogue. Choose small, medium or large only to document a model that is not in the catalogue. An existing instance that still says "small" for a catalogued model gets one short note instead of a warning.

##### Guardian Foundry

- New **Model** dropdown (cohere-command-a, Mistral-large, Mistral-Large-3, gpt-oss-120b, Llama-4-Maverick, DeepSeek-V3.2, Kimi-K2.6, gpt-5, gpt-5-mini, gpt-4.1, gpt-4o, or Custom). The choice is sent as the deployment name, so deploy the model under its own name; to switch models, change the dropdown. Existing instances keep using their Deployment name (Custom).
- A gpt-oss tool call that arrives as text in the model's own format (`to=functions.NAME ... <|call|>`) is now turned into a real tool call. Without it the loop saw an empty turn twice and ended with no verdict (2 of 50 runs in a test).
- New authentication type **entra-client-certificate**: a Microsoft Entra ID service principal that signs in with a certificate instead of a secret. Paste the certificate and private key as PEM (with an optional passphrase and thumbprint); the integration signs a client assertion (RS256) and caches the token like the secret type. Common Entra ID errors (`AADSTS700027`, `AADSTS700024`, `AADSTS7000215`) now come with a plain explanation. A cached token is no longer reused after the authentication type, tenant or client id changes.
- The integration now runs in the `demisto/crypto` docker image (it was `demisto/python3`), which provides the library used to sign the assertion. This applies to every authentication type; a server without internet access must have the new image available before the pack is upgraded.

#### Playbooks

##### GuardianInvestigateIssue

- The investigation prompt now contains the issue number, tells the model never to ask for it, asks for a plain-text similar-issue search and a knowledge-base lookup, and says a failed or empty search is not a reason to answer Inconclusive. An alert's own text is a detector's claim: with no tool result that corroborates it the verdict is Suspicious (confidence 40 to 70), not Malicious.
